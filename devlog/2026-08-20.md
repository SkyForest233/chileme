## 第 3 轮：CI 首轮失败 → AGP 9 内置 Kotlin 迁移

### ⚠️ 问题
CI `assembleDebug` 在配置/解析阶段快速失败（约 35s，未进入编译）。原因：**AGP 9.0+ 内置 Kotlin，`org.jetbrains.kotlin.android` 插件已不兼容**（与内置 Kotlin 冲突，配置期报错）。

### ✅ 修复
- 移除 `org.jetbrains.kotlin.android`（根 build.gradle.kts 的 `apply false` 声明 + app 模块的 plugins）
- 保留 `org.jetbrains.kotlin.plugin.compose` / `org.jetbrains.kotlin.plugin.serialization`（2.4.10，二者携带 KGP，供内置 Kotlin 使用）
- `kotlin { compilerOptions { jvmTarget = JvmTarget.JVM_17 } }` 采用官方迁移形态（赋值而非 `.set()`）
- Miuix 依赖坐标改用 common（`miuix-ui` / `miuix-preference`，与上游 README / release notes 一致，Gradle Module Metadata 自动解析 android 变体）

### 💡 决策
- 参照 Hyper-pick-up-code（AGP 9.x + 仅 compose/serialization 插件、无 kotlin.android 且构建通过）验证迁移形态
- `android.nonTransitiveRClass=true` 现为 AGP 9 默认值，保留无害；gradle.properties 无 AGP 9 禁用项（enableJetifier / enableDexingArtifactTransform 等均未使用）

### 📋 待办

## 第 5 轮：CI 失败 → Maven Central 间歇 403（网络，非代码）

### ⚠️ 问题
`Could not GET 'https://repo.maven.apache.org/...' → 403 Forbidden`：CI runner 拉取依赖时被 Maven Central 限流（guava / commons-compress / kotlin-stdlib / AGP 自身依赖等大量解析失败）。上一轮同环境可正常解析依赖，属间歇性网络故障（GitHub Actions 共享 IP 被 CDN 限流的已知问题）。

### ✅ 修复
- gradle.properties 增加依赖下载重试：`org.gradle.internal.repository.max.retries=8` + `initial.backoff=1000`，提升对瞬时 403 的容错

### 📋 待办
- 重新触发构建；若仍 403，考虑 workflow 层面重试 / 镜像仓库 / 分时段重跑
