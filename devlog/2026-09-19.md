### 1. `tools/move-importcheck.py` 补两条判据 —— 都是 10b 开工前的前置核查逼出来的

搬 `AppViewModel` 之前先拿领域 1（备份导入导出，9 个函数）做**纸上演练**：把要搬的 9 个块喂给工具、

（漏 import 只有编译器抓得到）。

**① 判据 4 补第 4 种形状：小写扩展「属性当接收者用」**

- 形状：`viewModelScope.launch { … }` —— 点号**前面**那个名字（`viewModelScope`）也是个需要 import 的扩展属性。
- 原判据 4 只认三种：`.name(` / `.name {` / `.name<`（点号后调用）、`数字.name`（`20.dp`）、
  裸 `name(` / `name {` / `name<`（直接调用）。`viewModelScope` 在这三种里一个都不占：
  它既不在点号后、也不带括号、后面跟的是 `.`。
- 实测（去注释口径，用 `kt-lexcheck.lex()` 剥注释后再数）：VM 代码里 `viewModelScope` 共 **58** 处、
  其中 `viewModelScope.launch` **38** 处，全是这个形状；领域 1 那 9 个块里占 **4** 处
  （`saveLocalSnapshot` / `restoreLocalSnapshot` / `importBackupWithSnapshot` 等）。
- 修法：`used()` 增加形状 `(?<![\w$.])name\s*\.`；新增自检对照 ⑨ `bare_property_chain`
  （期望点名 `['launch', 'viewModelScope']` —— 点号后的 `launch` 本来就能认，所以两个名字都在期望里）。

**② 判据 7：带接收者的声明不压制同名 import**

- 现象：新文件只算出 **7** 条 import，应为 **11** 条 —— 缺的 4 条是
  `com.agon.app.data.buildBackupJson` / `buildCsvExport` / `previewBackup` / `importBackupJson`。
- 根因：这 4 个名字在 `data/` 里是 `FoodRepository` 的**同名扩展**
  （`data/FoodBackup.kt:43/67/89/106`、`data/CsvExport.kt:9`），VM 第 32–35 行都 import 着；
  而搬走的函数**自己也叫这些名字**（`internal suspend fun AppViewModel.buildCsvExport(): String = repo.buildCsvExport()`）
  ⇒ `local_decls()` 把声明名收进「本地名」集合，`analyse()` 的第一道闸 `if name in decl: continue`
  直接把 import 压掉了。体内 `repo.buildCsvExport()` 要的恰恰是那条被压掉的 import。
- 修法：`local_decls()` 末尾减去 `RECEIVER_DECL_RE` 的捕获（`fun|val|var Receiver.name` 里的 `name`）。
  **减法放在最后**，免得被上面几条并集又并回来。
- 方向选择：真被本地声明遮蔽时会**多报**一条 import —— 多一条不红 CI（本仓 `no-unused-imports` 没开，
  死 import 由 `kt-lexcheck` 在本地兜），漏一条必红 ⇒ 取安全方向，写进判据 7 的 ⚠️ 与盲区 ⑤。
- 新增自检对照 ⑩ `receiver_decl_same_name`（`internal suspend fun AppViewModel.buildCsvExport(): String = repo.buildCsvExport()`
  ⇒ 期望点名 `['buildCsvExport']`）。
