   - 设置页云同步区新增间隔选择 Chip：关闭 / 每天 / 3 天 / 每周

### 💡 决策
- 密码加密选 Keystore + AES-GCM 而非 EncryptedSharedPreferences：security-crypto 库已弃用，自实现 60 行且无第三方依赖
- 自动同步在应用启动时触发而非 WorkManager 后台任务：用户明确"不做推送/后台"，启动时检查间隔已满足"每 N 天一次"语义且零电耗
- 消耗记录聚合粒度选「月 × 名称」：排行榜和月度统计是仅有的两个长期视图，该粒度对两者都无损
- 归档合并条件选「同名 + 同生产日期」：同一批次唯一可靠标识；仅同名不同批次合并会篡改过期日期
- 主题渐变自实现 animateColorScheme 而非 MaterialKolor DynamicMaterialTheme(animate=true)：后者只覆盖种子色路径，无法让动态取色/深浅切换也渐变

## 第 3 轮：修复日历圆点颜色不区分（用户截图反馈）

### ✅ 已完成
- **问题定位**：日历圆点此前用 `StatusUi.content` 上色。content 是为**文字可读性**设计的深色调（浅色模式下安全=墨绿 #12503A、临期=深棕 #7A4A00、过期=暗红 #8C1D18），明度相近、饱和度低，在 6dp 小圆点上肉眼几乎无法区分（用户截图中全部看起来是深色点）
- **修复方案**：`StatusUi` 数据类新增 `dot` 字段——小面积色块专用高饱和色，色相差异拉大：
  - 浅色：鲜绿 `#2E9E5B` / 琥珀橙 `#F59E0B` / 鲜红 `#E5484D`
  - 深色：`#4ADE80` / `#FBBF24` / `#FF6B6B`（深底上提亮保对比）
- `ExpiryCalendar.kt` 的 DayCell 圆点与底部图例 LegendDot 改用 `ui.dot`；徽章/文字/进度条等大面积场景继续用 content（可读性优先），互不影响
- 构建：✅ 成功（63.0 MB）

### 💡 决策
- 不直接调亮 content 色而是新增 dot 字段：content 承担文字对比度职责（WCAG 4.5:1），调亮会破坏所有徽章/正文场景；小圆点与文字对颜色的需求本质不同（辨识度 vs 可读性），分离成两个语义槽位
- 高饱和色选自通用信号色系（绿/琥珀/红），与主题种子色解耦，任何配色方案下语义不变

## 第 4 轮：Release 正式签名配置（keystore.properties 分离凭据）

### ✅ 已完成
- **生成固定 release keystore**（`release.keystore`，项目根目录）：RSA 2048、有效期 30 年（10950 天）、alias `chileme`；此文件为唯一正式签名，不再重新生成
- **凭据外置**：新建 `keystore.properties`（项目根目录）保存 storeFile/storePassword/keyAlias/keyPassword；`app/build.gradle.kts` 顶部读取该文件，文件不存在时 `hasReleaseSigning=false`
- **signingConfigs 改造**：新增 `create("release")` 从 properties 取值；release buildType 的 signingConfig 三元回退——有 keystore.properties 用 release 签名，无则回退 debug 签名（保证无密钥环境构建不失败）
- **R8 配置保留**：isMinifyEnabled = true、isShrinkResources = true、proguard 规则未动
- **新建 `.gitignore`**：排除 `keystore.properties`、`*.keystore`、`*.jks`（`!debug.keystore` 例外保留），另含 build/、.gradle/、.idea/ 等常规项
- **验证**：assembleRelease 成功产出 app-release.apk（2.6 MB）；apksigner 确认证书 DN=CN=ChiLeMe、SHA-256 指纹与 release.keystore 一致（e772c6f3...）；debug 构建不受影响（✅ 63.0 MB）
- 消除待办：「上架前需配置正式 release 签名」已完成

### 💡 决策
- 凭据放 keystore.properties 而非 build.gradle.kts 硬编码：密钥不入库（gitignore），CI 由 Secrets 动态生成同名文件，本地与 CI 走同一条读取路径
- 缺失 properties 时回退 debug 签名而非报错：协作者克隆仓库后无需密钥即可跑通 release 构建验证
- debug.keystore 显式保留在仓库（`!debug.keystore` 例外）：团队共享调试密钥，无安全价值，入库保证所有环境 debug 签名一致
