## 第 3 轮：修复日历圆点颜色不区分（用户截图反馈）

### ✅ 已完成
- **问题定位**：日历圆点此前用 `StatusUi.content` 上色。content 是为**文字可读性**设计的深色调（浅色模式下安全=墨绿 #12503A、临期=深棕 #7A4A00、过期=暗红 #8C1D18），明度相近、饱和度低，在 6dp 小圆点上肉眼几乎无法区分（用户截图中全部看起来是深色点）
- **修复方案**：`StatusUi` 数据类新增 `dot` 字段——小面积色块专用高饱和色，色相差异拉大：
  - 浅色：鲜绿 `#2E9E5B` / 琥珀橙 `#F59E0B` / 鲜红 `#E5484D`
  - 深色：`#4ADE80` / `#FBBF24` / `#FF6B6B`（深底上提亮保对比）
- `ExpiryCalendar.kt` 的 DayCell 圆点与底部图例 LegendDot 改用 `ui.dot`；徽章/文字/进度条等大面积场景继续用 content（可读性优先），互不影响
- 构建：✅ 成功（63.0 MB）

### 💡 决策
- 不直接调亮 content 色而是新增 dot 字段：content 承担文字对比度职责（WCAG 4.5:1），调亮会破坏所有徽章/正文场景；小圆点与文字对颜色的需求本质不同（辨识度 vs 可读性），分离成两个语义槽位
- 高饱和色选自通用信号色系（绿/琥珀/红），与主题种子色解耦，任何配色方案下语义不变

## 第 5 轮：修复 GitHub Actions 构建失败（debug.keystore not found）

### ⚠️ 问题
CI 报错 `Execution failed for task ':app:validateSigningRelease' — Keystore file '.../debug.keystore' not found for signing config 'debug'`。原因链：
1. 远端仓库中不存在 `debug.keystore`（未被提交，或受 `*.keystore` 忽略规则影响未 add 成功）
2. `signingConfigs.debug` 硬编码 `storeFile = file("$rootDir/debug.keystore")`，文件缺失时任务直接失败
3. CI 无 keystore.properties → release 回退 debug 签名 → validateSigningRelease 先触发此错误

### ✅ 修复（app/build.gradle.kts）
- 新增 `projectDebugKeystore = rootProject.file("debug.keystore")` 存在性检查
- debug signingConfig 改为**条件覆盖**：文件存在才指定项目内密钥；缺失时不设置 storeFile，AGP 自动回退默认调试密钥（`~/.android/debug.keystore`，不存在会自动生成）→ CI 无需任何密钥文件即可构建
- 验证：本地 debug 构建 ✅（63.0 MB）；临时移走 debug.keystore 后 `validateSigningRelease validateSigningDebug` 均通过 ✅

### 💡 决策
- 选"条件回退"而非"在 CI 生成密钥文件"：零 workflow 改动，任何环境（本地/CI/协作者）都能开箱构建
- 注意副作用：无项目密钥的环境使用 AGP 自动生成的调试密钥，**CI 产物与本地 debug 签名指纹不同**（覆盖安装需先卸载）。如需一致，把 debug.keystore 提交入库即可（`git add -f debug.keystore`，gitignore 已有 `!debug.keystore` 例外）
- 正式发布不受影响：CI 配好 Secrets 生成 keystore.properties 后，release 走 release.keystore 正式签名，与 debug 密钥无关
