## 第 1 轮：打 v* tag 自动发布 GitHub Release

### ✅ 已完成

- 改造 `.github/workflows/release.yml`：
  - 触发：`push` 到 `v*` tag（如 `v2.8.0`）自动跑；保留 `workflow_dispatch` 手动触发（默认分支 master）
  - 构建与签名步骤保持原样：`actions/checkout@v5`、`actions/setup-java@v5`（temurin 17）、`secrets.KEYSTORE_BASE64` 解码 keystore、`./gradlew assembleRelease`（env 注入 `RELEASE_KEYSTORE_PATH/PASSWORD/ALIAS/KEY_PASSWORD`）
  - 新增 changelog 提取步骤：跑 `.github/scripts/extract_changelog.py`，从 `devlog/` 最新日期文件抽取「## 第 N 轮」里「### ✅ 已完成 / ### ✅ 修复」段落要点，写入 `release_notes.md` 与 `$GITHUB_ENV`；失败或为空回退「无更新日志」
  - 用 `softprops/action-gh-release@v2` 创建 Release：`tag_name`/`name` 均为 `${{ github.ref_name }}`，`body_path` 为上一步的说明，`files` 指向 `app/build/outputs/apk/release/*.apk`，`GITHUB_TOKEN` + `permissions: contents: write`
  - 仅当 `github.ref` 为 `refs/tags/v*` 时创建 Release，避免在 master 上手动触发误建名为 `master` 的 Release；原有 `upload-artifact` 保留，手动跑分支仍能拿到 APK
- 新增 `.github/scripts/extract_changelog.py`（本地用 2026-08-20 / 2026-08-01 两份日志验证：分别抽出 38 / 6 个轮次）
- 同步 `docs/WORKFLOW.md` 新增 §6 发布说明

### 💡 决策

- 「### ✅ 修复」与「### ✅ 已完成」同等抽取：本仓库大量轮次用「修复」标题记录完成项，只抽「已完成」会漏掉大部分要点
- 不抽非「第 N 轮」的章节（如 2026-08-20 开篇「主题风格切换」）：严格按需求过滤
- Release 创建加 `startsWith(github.ref, 'refs/tags/v')` 门控：`workflow_dispatch` 在 UI 里选中 v* tag 仍会发布；选分支则只上传 artifact
- 本轮只改 CI / 文档，无 Android 代码变动，不跑 `assembleDebug`
