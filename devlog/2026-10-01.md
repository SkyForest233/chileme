# 2026-10-01 —— 根据新一轮真机反馈修复多页 Tab 抽动与阴影延迟

> 用户复测指出：液态玻璃底栏上缘阴影仍延迟；点击跨过一个以上位置的 Tab 时指示器/页面抽动。重新核对 Miuix v0.9.4 **demo app 的 Pager 协调器与导航显隐层**，不只看独立导航组件。

## 🔍 源码对照与根因

- Miuix demo 的 `example/shared/.../AppContent.kt` 用 `MainPagerState` 单独维护 `selectedPage` 与 `isNavigating`。触发导航时先把 selected target 更新到最终页；Pager 动画经过中间 `currentPage` 时，`syncPage()` 因 `isNavigating` 而不回写选中态。项目原来直接把 `PagerState.currentPage` 传给液态玻璃栏；从第 0 页跳第 3 页时，`LaunchedEffect(selectedIndex)` 会先收到中间页索引，反复把指示器动画目标改回中间页，正好对应真机抽动。
- Demo 的 `MainPagerState.animateToPage()` 调用 Miuix v0.9.4 `PagerGestureUtils.kt` 的 `PagerState.springAnimateToPage()`，它在同一 Pager scroll mutation 中以实际像素距离做一次连续弹簧滚动；本项目先前使用 Compose `animateScrollToPage()` + 自制 distance response，两边对长距离预定位/中间页同步的行为并不等价。
- Demo app 的底栏显隐使用 `fadeIn + expandVertically` / `fadeOut + shrinkVertically`，本项目先前对整条悬浮栏使用 `slideInVertically / slideOutVertically`。液态玻璃阴影外扩 10dp，推测 slide 容器裁切/揭示时序让上缘影子比栏体晚进入绘制区域；仅调整 `dropShadow` 和 backdrop 的前后顺序没有覆盖这一层。

## ✅ 本轮修复

- 新增 `MainTabsPagerState`，按 demo 将导航目标与 `PagerState.currentPage` 解耦；导航期间不把中间页写回选中态。仅 MIUIX 使用 Miuix `springAnimateToPage()`；Material 3 保留原来的 distance-based `MotionSpring.page()` 动画。点击与拖拽仍共用同一个 `selectTab` 入口。
- MIUIX 悬浮栏显隐改为 demo 风格 `fade + expand/shrink`，并关闭尺寸转场裁剪 (`clip=false`)；Material3 与其他导航形态保留原 slide 动画。
- 对自定义玻璃栏及 Miuix 库常规悬浮栏各预留 12dp 上缘空间，覆盖 10dp shadow outset；组件最终锚点由底部 padding 决定，增加的测量空间不会下移胶囊。这样 shadow 不必溢出 AnimatedVisibility 的裁剪边界才可见。
