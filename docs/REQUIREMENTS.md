# 需求规格说明（REQUIREMENTS）

> 版本：v2.0 · 状态：已实现并验收
> 本文档是功能范围的唯一事实源。新需求必须先在此登记再开发。

## 1. 产品定位

家庭场景的零食/食品库存管理 App：记录食品信息，自动计算过期日期，临期提醒，减少浪费。本地单机、无后端。

## 2. 功能清单（v1.0 基础）

| 编号 | 功能 | 要点 |
|---|---|---|
| F1 | 食品记录 CRUD | 名称、分类(8类)、数量+单位、生产日期、保质期(天)、备注 |
| F2 | 过期计算 | 过期日 = 生产日期 + 保质期；实时显示剩余天数与新鲜度进度条 |
| F3 | 三色状态 | 安全(绿) / 临期(橙黄) / 过期(红)；深浅色各自适配 |
| F4 | 首页 Dashboard | 总数/临期/过期统计卡、今日提醒、需要处理列表 |
| F5 | 食品列表 | 搜索、状态/分类筛选、**长按多选批量归档（v2.3，取代滑动删除）**(可撤销)、卡片内数量步进器 |
| F6 | ~~OCR 识别生产日期~~ | **已移除（v2.3）**：识别率低，用户确认下线；日期改为纯手动选择 |
| F7 | 主题 | 深色模式三档(跟随/浅/深)、Android 12+ 动态取色开关 |
| F8 | 首启种子数据 | 8 条示例（含临期与过期项），仅首次写入 |

## 3. 功能清单（v2.0 增量，用户已确认）

| 编号 | 功能 | 要点 |
|---|---|---|
| F9 | 临期阈值自定义 | 按分类设默认阈值（设置页，1~365 天，默认 7）；单条记录可覆盖（编辑页开关）；优先级：单条 > 分类 > 默认 7 天 |
| F10 | 存放位置 | 自由输入 + 预设 Chip（零食柜/冰箱/厨房/储物间/客厅/卧室）；列表按位置筛选；卡片显示位置标签 |
| F11 | 照片封面 | 拍照（FileProvider）或相册选图；图片复制到私有目录 `files/covers/`；可移除；无照片时回退分类 emoji |
| F12 | 历史记忆录入 | 保存时记入历史（最多 50 条，同名去重）；添加时名称联想，一键带出分类/单位/保质期/位置；仅新增模式显示 |
| F13 | 统计页 | 本周/本月消耗、过期浪费数；近 7 天消耗柱状图；库存分类占比环形图；消耗排行 TOP5；与分类占比同一页面 |
| F14 | 本地备份 | SAF 导出/导入 JSON；包含库存、归档、消耗记录、历史、阈值设置；导入为整体替换；格式错误友好提示 |
| F15 | 消耗打卡动效 | 详情页“吃掉一份！😋”大按钮；封面弹跳 + emoji 上浮渐隐 + 连击计数；消耗计入统计 |
| F16 | 过期一键清理 | 首页有过期项时显示按钮，批量移入归档（原因：过期清理） |
| F17 | 归档历史 | 所有删除类操作进归档（上限 200 条）；区分原因：已删除/已吃完/过期清理；支持按原因筛选、恢复、彻底删除、清空；入口在设置页 |

## 4. 明确不做（需求边界，用户已确认）

- ❌ 推送通知 / 后台提醒（WorkManager）
- ❌ 补货/购物清单
- ❌ 桌面小组件（Widget）
- ❌ 条形码扫描、外部商品库 API
- ❌ 多人协作 / 云同步 / 任何后端

如需新增以上功能，必须先与用户确认并更新本文档。

- ❌ OCR 日期识别（v2.3 起下线，用户确认“识别率低、鸡肋”；不得重新引入 ML Kit）

## 5. 验收标准

1. `./gradlew assembleDebug` 构建成功，无编译错误
2. 每个功能点可完整走通：添加 → 列表/首页展示 → 编辑 → 消耗 → 归档 → 恢复
3. 数据重启 App 后不丢失（DataStore 持久化）
4. 深色/浅色/动态取色下 UI 均可读，状态色对比度足够
5. 空态、错误态（如导入格式错误）有友好提示
